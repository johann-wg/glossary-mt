# 障害報告書：出荷指示データの連携遅延

## 1. 障害概要

| 項目 | 内容 |
|---|---|
| 発生日時 | 2026年10月21日（水）03:15 |
| 復旧日時 | 2026年10月21日（水）05:40 |
| 影響範囲 | 配送センター 3 拠点の出荷指示 約1,200件 |
| 重要度 | 高 |

## 2. 経緯

- 03:15 監視ツールが夜間バッチの処理時間超過を検知しました
- 03:30 担当者が切り分けを開始し、DB サーバーのディスク使用率が 95% に達していることを確認しました
- 04:10 暫定対応として不要なログファイルを削除し、ジョブネットを再実行しました
- 05:40 すべての出荷指示データの連携が完了したことを確認しました

## 3. 原因

ログローテーションの設定漏れにより、`/data/dms/logs` 配下のログファイルが約 3 か月間削除されていませんでした。
これにより、ディスク使用率が閾値を超え、バッチ処理が待機状態になりました。

## 4. 再発防止策

- 恒久対応として、本番環境と検証環境の全サーバーにログローテーションを設定します（11月7日完了予定）
- ディスク使用率の監視閾値を 80% に下げ、通知先にお客様の担当者を追加します
- 手順書にディスク容量の確認手順を追加し、申し送り時の確認項目として管理します

お客様には多大なるご迷惑をおかけしましたことを深くお詫び申し上げます。
