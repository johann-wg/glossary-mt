# glossary-mt

日本語・韓国語の技術文書（**Markdown / Excel / PowerPoint**）を、**書式を保ったまま、用語集どおりに**翻訳する Python CLI です。
翻訳には Claude API（Anthropic）を使い、訳文は**コードで品質チェック**して、問題があれば問題点を伝えて自動で再翻訳させます。
QA を通った訳文は翻訳メモリ（SQLite）に保存し、文書を一部修正して再実行したときは**変更した文だけ**を翻訳します。

```
$ glossary-mt translate proposal.ja.pptx 04_batch_runbook.ja.md 05_parameter_sheet.ja.xlsx \
    --to ko --glossary data/glossary.csv --model claude-haiku-5-5
proposal.ja.pptx → proposal.ko.pptx: 翻訳対象 18 件 (重複を除き 18 件: 翻訳メモリ 0 / 新規翻訳 18, うち再翻訳で修正 0) / 要確認 0 / 警告 0
04_batch_runbook.ja.md → 04_batch_runbook.ko.md: 翻訳対象 28 件 (重複を除き 28 件: 翻訳メモリ 0 / 新規翻訳 28, うち再翻訳で修正 0) / 要確認 0 / 警告 0
05_parameter_sheet.ja.xlsx → 05_parameter_sheet.ko.xlsx: 翻訳対象 46 件 (重複を除き 37 件: 翻訳メモリ 0 / 新規翻訳 37, うち再翻訳で修正 0) / 要確認 0 / 警告 0
API 呼び出し 4 回 / キャッシュ利用 0 回 / 費用 約 $0.0038

# 手順書の 2 行を修正して再実行 → 変更のない 26 文は翻訳メモリから、API に送るのは 2 文だけ
$ glossary-mt translate 04_batch_runbook.ja.md --to ko --glossary data/glossary.csv --model claude-haiku-5-5
04_batch_runbook.ja.md → 04_batch_runbook.ko.md: 翻訳対象 28 件 (重複を除き 28 件: 翻訳メモリ 26 / 新規翻訳 2, うち再翻訳で修正 0) / 要確認 0 / 警告 0
API 呼び出し 1 回 / キャッシュ利用 0 回 / 費用 約 $0.0003
```

出力例は [examples/out/](examples/out/) にあります（[PowerPoint](examples/out/proposal.ko.pptx)・[Excel](examples/out/05_parameter_sheet.ko.xlsx)・[Markdown](examples/out/04_batch_runbook.ko.md)・[QA レポート](examples/out/qa_report.md)）。

## 背景

日韓の技術連携の業務で、設計書・手順書・障害報告書・管理表の日韓翻訳を担当しています。
汎用の機械翻訳や LLM にそのまま訳させると、次のような問題が繰り返し起きます。

- **顧客ごとの用語が守られない**: 「本番環境」を「운영 환경」と呼ぶ顧客に「프로덕션 환경」と訳す、「帳票」を「장표」と直訳する
- **書式が崩れる**: Excel や PowerPoint からテキストをコピーして訳し、貼り戻す作業に時間がかかる
- **コマンドや数値が変わる**: パスやコマンドの一部が訳されたり、数値が書き換わったりしても気づきにくい
- **修正のたびに全文を訳し直す**: 文書の一部を直しただけでも、毎回全体を確認し直す必要がある

これらを自動化しつつ、**LLM の出力を機械的に検証できる形**にすることを目指しました。

設計で重視した点:

- **確認できることはコードで確認する**: 用語集の訳語・数値・保護部分（コード・URL・パス）・文字種・韓国語の助詞を、LLM の自己申告ではなく機械的にチェックする
- **書き換えてはいけない部分は LLM に渡さない**: コードや URL は `⟦1⟧` のようなマーカーに置き換えてから送り、翻訳後に戻す。マーカーが消えた・増えた場合は検出する
- **増分処理で費用と確認の手間を減らす**: 翻訳メモリのキーに「適用された用語の組」を含め、原文か用語集の該当部分が変わった文だけを再翻訳する
- **評価で効果を測る**: 参照訳との比較で、用語集の指定や再翻訳がどれだけ効いているかを構成ごとに測定する
- **再現性**: LLM の応答をキャッシュしてコミットし、API キーがなくても CI で同じ評価結果を再現できる

## 仕組み

```
 文書 ──> formats (Segment に分解) ──> 重複排除 ──> 翻訳メモリ (SQLite) ──┬──────────────> 書き戻し (書式はそのまま)
                                                       │ ヒットなし               │
                                                       └─> protect (コード・URL をマーカーに置換)
                                                             └─> translate (Claude API, asyncio で並列) ──> qa ──┤
                                                                     ↑                                           │
                                                                     └──── error: 問題点を伝えて再翻訳 ─────────┘
                                                                                  QA 通過分を翻訳メモリに登録
```

| モジュール | 役割 |
|---|---|
| `formats/` | 形式ごとのアダプター（`Document` プロトコル）。Markdown は行単位で構文を残して本文だけを、Excel は文字列のセルだけを、PowerPoint は図形・表・グループ・ノートの段落を扱う |
| `protect.py` | インラインコード・URL・パス・メールアドレス・`{変数}`・`%s` などをマーカーに置換し、翻訳後に復元。マーカーの欠落・重複を検出 |
| `glossary.py` | 用語集（CSV）の照合。長い用語に含まれる短い用語は除外し、韓国語の分かち書きの揺れは無視する |
| `translate.py` | 文を件数・文字数の上限でまとめて 1 リクエストにし、`asyncio` + `Semaphore` で並列送信。JSON スキーマで出力形式を固定。出力が上限に達したら半分に分けて再送。応答キャッシュと費用の集計 |
| `qa.py` | 訳文の機械チェック（下表） |
| `pipeline.py` | 重複排除 → 翻訳メモリ → 翻訳 → QA → 再翻訳 → 書き戻し。再翻訳で悪化した場合は前回の訳を残す |
| `tm.py` | 翻訳メモリ（SQLite）。キーは「原文 + 適用された用語の組」 |
| `watch.py` | フォルダを監視し、保存された文書を自動で翻訳する（更新日時とサイズのポーリング、標準ライブラリのみ） |
| `evaluate.py` | 参照訳との比較（chrF・用語集準拠率・数値保持率・保護部分保持率）。chrF は自前で実装 |

### QA のチェック項目

| 種類 | 内容 | 重大度 |
|---|---|---|
| 用語集 | 原文に用語集の語があるのに、指定の訳語が訳文にない | error |
| 保護部分 | マーカーが消えた・重複した | error |
| 数値 | 原文の数値が訳文にない（全角・桁区切り・「一次」「일차」「1차」のような序数の表記差は無視） | error |
| 助詞 | 数字で終わる語の後の韓国語の助詞の誤り（例: `2.4.0를` → `2.4.0을`。0 は「영」でパッチムあり） | error |
| 文字種 | 韓国語の訳文に仮名・日本語の句読点・中黒「・」が残っている | error |
| 文字種 | 日本語の訳文にハングル、韓国語の訳文に漢字が残っている（人名などの可能性があるため） | warning |
| 長さ | 原文と訳文の長さが大きく違う | warning |

error が残った文は QA レポート（Markdown）の「要確認」に原文・訳文・問題点を並べて出力します。

## 使い方

```bash
git clone https://github.com/johann-wg/glossary-mt.git
cd glossary-mt
pip install -e ".[pptx]"     # PowerPoint を使わなければ pip install -e .

# ANTHROPIC_API_KEY を設定して実行 (翻訳元の言語は --to の反対側)
glossary-mt translate 設計書.xlsx 手順書.md --to ko --glossary data/glossary.csv
glossary-mt translate 障害報告書.ko.md --to ja --glossary data/glossary.csv --model claude-haiku-5-5

# フォルダを監視し、保存されたファイルを自動で翻訳する
glossary-mt watch docs/ --to ko --glossary data/glossary.csv --out-dir out

# 評価 (キャッシュのみ使用・API キー不要)
glossary-mt eval data/test --glossary data/glossary.csv --model claude-sonnet-5-5 --offline
```

- 出力は `out/<名前>.<言語><拡張子>`、QA レポートは `out/qa_report.md`
- `--model` を省略した場合は `claude-opus-5-5` を使います。実行後に API 呼び出し回数と費用が表示されます
- `--strict` を付けると、要確認の文が残ったときに終了コード 1 を返します（CI での利用を想定）

用語集は `ja,ko,note` の 3 列の CSV です（[例](data/glossary.csv)）。1 行が 1 組の対訳で、日→韓・韓→日の両方向に使います。

## 評価結果

評価データは架空の物流会社の配送管理システムを題材にした文書 6 件で、参照訳は人手で作成しました（業務のデータは一切含みません）。

| データ | 文書 | 用途 |
|---|---|---|
| `data/dev/` | リリース手順書（日→韓, Markdown）・課題管理表（日→韓, Excel）・作業結果報告（韓→日, Markdown） | 開発用。プロンプトと QA の調整に使用 |
| `data/test/` | 障害対応手順書（日→韓, Markdown）・監視設定パラメータシート（日→韓, Excel・2 シート）・障害報告書（韓→日, Markdown） | **評価専用**。プロンプトの調整には使わない。参照訳は実行前に作成して固定 |

### 評価専用データでの結果

| モデル | chrF | 用語集準拠率 | 数値保持率 | 保護部分保持率 | 要確認が残った文 | 原文 1 万文字あたり費用 |
|---|---|---|---|---|---|---|
| Claude Haiku 5.5 | 88.2 | 62/62 | 24/24 | 5/5 | 0/90 | 約 $0.03 |
| Claude Sonnet 5.5 | 92.7 | 62/62 | 24/24 | 5/5 | 0/90 | 約 $0.32 |
| Claude Opus 5.5 | 95.1 | 62/62 | 24/24 | 5/5 | 0/90 | 約 $0.60 |

構成ごとの効果（chrF / 用語集準拠率）:

| モデル | 用語集なし | + 用語集をプロンプトに指定 | + QA で検出した誤りを再翻訳 |
|---|---|---|---|
| Claude Haiku 5.5 | 80.2 / 52% | 88.2 / 100% | 88.2 / 100% |
| Claude Sonnet 5.5 | 83.7 / 56% | 92.2 / 100% | 92.7 / 100% |
| Claude Opus 5.5 | 84.5 / 55% | 95.1 / 100% | 95.1 / 100% |

各モデル 1 回ずつの結果です（[docs/model-comparison.md](docs/model-comparison.md)、`scripts/compare_models.py` で生成）。文書数が少ないため、差の大きさより誤りの内容を重視しています。

- **用語集の指定が最も効く**: 用語集なしでは、どのモデルも約半数の用語を一般的な訳語（「검증 환경」「장표」「임계값」「항구 대응」など）にしており、指定すると全モデルで 100% になった
- **再翻訳は「最後の網」**: Sonnet は監視設定シートの「運用チーム・お客様」を `운영팀・고객사` と訳した。**日本語の中黒「・」(U+30FB) が韓国語の「·」(U+00B7) の代わりに残っており**、QA が検出して再翻訳で修正された。目視では見分けにくい誤り
- 安価な Haiku でも用語・数値・保護部分の誤りは 0 件で、chrF の差は主に言い回しの違い。費用は Opus の約 1/20

### 開発中の改善

| 問題 | 対応 |
|---|---|
| コードを保護したため、LLM が保護部分の読みを知らず `` `… 2.4.0`를 `` と助詞を誤った（正しくは「영」に続く「을」） | 各マーカーの元の内容を参考情報として渡し、助詞は読みの最後の音に合わせるよう指示。QA に助詞のチェックを追加 |
| QA が `이전 버전(v2.3.2)으로` を誤りと判定した（括弧の後の助詞は括弧の前の語に合わせるので正しい）。**Opus はこの誤った指摘に従って `(v2.3.2)로` に書き換え、訳文が悪化した** | 括弧の後の助詞をチェック対象から除外。QA の誤検知は再翻訳を通じて品質を下げるため、確実に判定できるものだけを error にする方針にした |
| 「一次切り分け」を Haiku が「일차 원인 분석」と訳し、数値の欠落と判定された（「일차」も正しい） | 日本語の漢数字と同様に、韓国語の「일차」「이차」なども算用数字にそろえてから比較 |
| コード中の `<日付>` が「韓国語の訳文に漢字が残っている」と警告された | 保護部分は原文と同一であることを別に保証しているため、文字種・用語・数値のチェックから除外 |

## 制限事項

- 対応言語は日本語と韓国語の 2 言語のみ
- Excel: シート名・コメント・入力規則のリスト・数式内の文字列（`COUNTIF(F:F,"完了")` など）は翻訳しない。openpyxl の制約で、画像・グラフを含むブックは書き戻し時に失われる
- PowerPoint: 段落内で書式が異なる部分（一部だけ太字など）は、段落先頭の書式にそろう
- Markdown: 複数行にわたる段落は行ごとに訳す

## 開発

```bash
pip install -e ".[dev]"
pytest -q                      # API は呼ばない (キャッシュのみ使用)
ruff check . && ruff format --check .
python scripts/make_samples.py # 評価データの Excel・サンプルの PowerPoint を再生成
```

テストには、パイプラインを辞書ベースの偽の Translator で検証するもの（翻訳メモリ・再翻訳・悪化時のロールバック）や、
Hypothesis によるマスク / 復元の性質テスト（任意の文字列で `unmask(mask(s)) == s`）を含みます。
